# Decisions & lessons

A running log of judgment calls and mistakes made while building and using this ICM — so the reasoning behind a rule doesn't live only in someone's memory of a conversation. Append to this whenever you make a real decision or catch a real mistake; don't let it go stale. New entries go at the top of each section.

## Decisions

- **`_system/portable/start-here/` exists as a fifth, deliberately tiny export** on top of the other four - 5 files (bundle.md, bundle.txt, brief-template.docx, the Gallagher example, one plain-English instructions file), no flattened names needed since there's no collision risk at that size. The other portable exports require understanding the difference between flat-files/flat-files-txt/bundle before picking one; this one doesn't require that decision at all - it's the default recommendation for anyone who just wants to drop files into a chat and go.
- **Path B+ (chat-only but code-capable) hands the target LLM the real `brief-template.docx`, not instructions to build a Word doc from scratch.** Two real .docx files (the template and the Gallagher example) were added as an exception to the "portable exports are text-only" rule, in `flat-files/` only, specifically for this - a from-scratch document would drift from the actual styling. The Path B+ prompt in `chat-only-workflow.md` explicitly calls out the header/footer and the "delete, don't blank out" handling of the optional portfolio section, because those are the two things this workspace's own build already got wrong once each (see Mistakes & fixes) - no reason to expect a different LLM would get them right by default either.

- **The `.txt` portable exports keep markdown notation - only the extension changes.** Considered stripping `#`/`**`/tables/etc. to plain prose for the `.txt` variants, but the actual consumer is an LLM reading the file, and LLMs parse markdown structure fine as plain text regardless of extension - stripping it would lose real information (table structure, emphasis) for no benefit. `.txt` exists purely to get past upload dialogs that filter by extension, not to change what's inside. If a human is going to read one of these files directly, `.md` in a markdown-aware app (Obsidian, VS Code) is the better choice either way.
- **A folder-free export exists (`_system/portable/`, built by `build_portable_bundle.py`)** for LLM platforms that can't take a zip or a nested folder upload — some only accept a flat list of individual files, others only a single upload or pasted text. Two outputs cover both: flattened individual files (path-encoded filenames, no subfolders) and one concatenated `bundle.md` with `<<<FILE: path>>>` markers. Binaries are excluded for the same reason as the chat-only CSV exports — they can't be usefully flattened into text.
- **A local copy of the ICM method lives in `_system/icm-method/`**, not just referenced from the repo root. Per the method's own "method and instance live apart" rule, this deployment shouldn't have to reach outside its own folder to understand or evolve its structure — the copy is frozen at the point it was pulled and won't auto-update if the root copy changes; see `_system/icm-method/ABOUT-THIS-COPY.md`.
- **Record library, not Pipeline.** The repeating unit is a senator record that accumulates state (pulled → validated → finalized), not a one-shot run — so this ICM uses the Record library form.
- **`finalize_send_pack.py` hard-gates on `validated: true`.** It refuses to produce a send-ready brief/email for an unvalidated record. This is the actual "ready to send" checkpoint, not the earlier render step (which will happily render an unfinished record for review purposes).
- **Sign-off identity (name/email) stays blank until the finalize stage**, deliberately — kept as its own human gate rather than baked in earlier, so nothing gets "signed" before a person is actually ready to send it.
- **Footprint estimate formula** (carers = 2× participants, family = 4× participants, community = 6× participants, total = sum of all): reverse-engineered from the numbers in the Gallagher example brief, since no formula existed in writing anywhere else. If this ever looks wrong, that's the origin — it wasn't independently sourced, it was inferred from one example.
- **Vote-position rule** treats Labor/Coalition/One Nation as "expected support" rather than "Unknown," even though no one has literally confirmed their vote — because they hold the ~61 votes needed to pass the bill, and calling it "Unknown" would hand them a rhetorical escape hatch the accountability framing is built to deny them. "Unknown" is reserved for senators whose vote is genuinely contestable, where it does real work by inviting them to declare a position.
- **Portfolio relevance requires a substantive link to the bill's harms**, not just any ministerial title — e.g. Minister for Women earned a lens because SCCP cuts foreseeably shift unpaid care onto women, not because "Minister for Women" sounds relevant. The approved category list lives in `portfolio-relevance.md`; don't invent new categories per-senator without adding them there first.
- **docx over HTML→PDF** for the brief format: a working, polished docx template already existed (the Gallagher example) to build from. HTML→PDF would mean rebuilding all that styling from scratch in CSS with no reference to copy, plus a new PDF-rendering dependency, for no real gain — docx is also the conventional, editable format for office correspondence anyway.
- **Vote-position rule, portfolio-relevance rule, and the fixed immediate-ask text live in their own files**, not inside `brief-template.md` — so they can be updated independently without touching the document structure ("one home per fact").

## Mistakes & fixes

- **The path-portability fix missed one file.** `extract_senator_data.py` and `render_brief_docx.py` were fixed to resolve their base path relative to the script's own location instead of a hardcoded machine-specific absolute path (see below), but `build_template_v2.py` - a one-off tool that had already served its purpose - still had the old hardcoded path, leaking the machine's Windows username to anyone who opened it. It also referenced the pre-restructure folder name, so it no longer even ran. Fixed by archiving it (`_archive/build_template_v2.py.orig`) rather than patching a script with nothing left to do. Also found the same username embedded in `__pycache__/*.pyc` files (Python bytecode records source paths) - added a root `.gitignore` for `__pycache__/`/`*.pyc` so this can't quietly recur. **Lesson:** when auditing for something (here: "does this leak identifying info before sharing"), check the *whole* workspace, not just the files you were actively working on that session - a fix applied to two of three similar files isn't done.
- **The portable bundle went stale within the same session it was built in.** Several reference files (`CLAUDE.md`, `chat-only-workflow.md`, `decisions-and-lessons.md` itself) were edited after `build_portable_bundle.py` had already run, and it wasn't re-run afterward - caught by explicitly verifying `_system/portable/` byte-for-byte against source rather than assuming a script that ran successfully once was still current. **Lesson:** any generated artifact needs to be re-verified (or just re-run) after later edits touch its inputs, not only checked once at creation time - "it worked when I built it" and "it's correct right now" are different claims.
- **Two of the three pipeline scripts hardcoded an absolute Windows path tied to one specific machine** (`BASE = Path(r"C:\Users\...")`), inconsistent with a third script that already resolved its base path relative to its own file location. This would have broken immediately the moment this workspace was copied anywhere else, run on a different OS, or handed to a different user — directly undermining the "works with any LLM/any user" goal. Fixed by making both scripts resolve `BASE` from `Path(__file__).resolve().parent.parent.parent`, matching the pattern the third script already used. **Lesson:** when multiple scripts in the same workspace solve the same problem (finding the workspace root) two different ways, that inconsistency is itself worth investigating — one of them is probably wrong.
- **Header/footer are a separate document part from the body.** A full-document bracket-fill pass touched every paragraph and table in the body but missed `doc.sections[].header`/`.footer` entirely — every rendered senator's document showed Katherine Gallagher's literal name in the page header, regardless of who the brief was actually for. Fixed by explicitly processing header/footer paragraphs. **Lesson:** when patching a docx, remember the document has parts beyond the main body.
- **YAML frontmatter can't use `{curly-brace}` placeholders.** `slug: {kebab-case-name}` got silently parsed as a YAML flow-map by the Obsidian linter, splitting it into nested keys and breaking the field. Fixed by using a quoted empty string instead. **Lesson:** placeholder syntax that's safe in markdown body text isn't automatically safe inside YAML frontmatter.
- **A build-time-only instructional note leaked into a real output.** The template's "(OPTIONAL — include only if the senator holds a relevant portfolio...)" annotation is documentation for whoever fills the template, not senator-facing content — it showed up in Gallagher's actual rendered brief because nothing stripped it when the section was kept (only the "remove entirely" path was handled, not the "keep it but clean it up" path).
- **Contact-list PDF parsing had several sharp edges**, all found by checking the parsed output against known-good data rather than trusting the regex on the first pass: nickname parentheses like "(Katy)" were swept in as if they were job titles; a two-word surname ("Nampijinpa Price") silently dropped that senator's entire entry; apostrophes in email addresses broke the email regex; a `**`-prefixed footnote row wasn't matched at all; and a state abbreviation appearing *inside* a procedural title (e.g. "(Independent ACT Whip)") could falsely trigger the parser's stop-boundary. **Lesson:** always spot-check parsed output against the source for a full known list (all 76 senators, not a sample), not just the couple of names you're actively testing.
- **A "missing" field wasn't actually missing.** Believed the base template's Male Electors row had been dropped and rebuilt it, creating a duplicate — the row was there all along and the earlier read of it was just wrong. **Lesson:** re-verify a "this is missing" claim against the actual current file before writing code to fix it, don't trust a memory of an earlier read.
- **A reference/legend table got filled with real data instead of staying as documentation.** The "Template field | Replace with" glossary table used the same bracket tokens as the real data tables, so a blanket find-and-replace pass filled it in too, putting data in the label column. Fixed by detecting true reference/legend tables (by header row) and excluding them from replacement.
- **Splitting extraction from rendering left one field's fallback value unhandled.** When a senator had no relevant portfolio, the checklist table's `[PORTFOLIO/MINISTERIAL RESPONSIBILITY]` bracket was only mapped in the "relevant" branch, so it went unfilled for everyone else. **Lesson:** after any refactor, re-run the leftover-bracket check across *every* affected output, not just the case you were actively working on.

## Known/ongoing gaps — worth knowing before you trust this blindly

- `senator-portfolios.md` is a dated snapshot (taken 2026-08-14). Portfolios change unexpectedly (reshuffles, resignations) — re-verify against the live APH Parliamentarian Search before relying on it, especially if it's been a while since the snapshot date.
- The portfolio-relevance keyword match is a starting point, not a verdict — see the "Borderline cases" section of `senator-portfolios.md` for ones that need a human judgment call either way.
- Only 4 of 76 senators (Gallagher, Hanson, Pocock, Steele-John) have actually been run through the full pipeline and spot-checked as of this writing. The other 72 haven't been extracted or validated yet.
