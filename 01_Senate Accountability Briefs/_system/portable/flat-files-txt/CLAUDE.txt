# Senate Accountability Briefs — NDIS Amendment Bill

A record library of 76 senators. Each senator's record accumulates data, gets validated by a human, then gets personalized and finalized into a Word brief + cover email, ready to send. See [`README.md`](README.md) for what this is and why; this file is routing only.

**Three paths, not just Claude Code:** scripted (`_system/tools/*.py`, needs Python + `openpyxl`/`pypdf`/`python-docx`/`PyYAML`), chat-only (paste a few files, no code execution), or folder-free (a flat/single-file export for platforms that reject zips and nested folders) — see [`01_reference/chat-only-workflow.md`](01_reference/chat-only-workflow.md) for all three. Check what the user actually has before picking one.

## Where things live

| Folder | What it holds |
|---|---|
| `01_reference/` | factory — brief template + field legend, vote-position rules, portfolio-relevance rules, senator-portfolios snapshot, source data (binary + plain-text CSV exports), bill text, campaign context, chat-only workflow guide, sender profile, one polished example |
| `_templates/` | blank stamps: `senator-record.md`, `personal-note.md` — new work is a copy, not a blank page |
| `_index/log.md` | one line per senator: slug, party, state, vote position, status — generated/rebuilt, never hand-edited |
| `records/` | one folder per senator: `record.md` (data + validation) and, later, `personal-note.md` (optional) |
| `_system/tools/` | pipeline scripts (below) + `_selection.py` (shared `--party`/`--state`/`--all`/name filtering) |
| `_system/icm-method/` | a local copy of the ICM method this workspace is built on (SKILL.md, references, templates) — so this deployment can be understood and evolved without reaching outside its own folder; see `ABOUT-THIS-COPY.md` there |
| `_system/portable/` | folder-free exports for platforms that reject zips/nested folders or filter by extension. `start-here/` is the 5-file minimum for someone who just wants to drop files into a chat with no further explanation — send them there first. `flat-files/`, `flat-files-txt/`, `bundle.md`/`bundle.txt` are the fuller, more granular options. All generated by `build_portable_bundle.py`, see `01_reference/chat-only-workflow.md` |
| `02_output/` | draft Word briefs from records, validated or not — regenerate any time, sign-off stays blank |
| `03_ready-to-send/` | finalized output: Word brief + plain-text cover email, per senator |
| `_archive/` | superseded template, old AI-instructions doc, drafts from before this workflow existed |

## Route by what just happened

| If | Go to |
|---|---|
| starting a new senator | `python _system/tools/extract_senator_data.py "Senator Name"` (or `--party`/`--state`/`--all`) → `records/{slug}/record.md` |
| checking a senator's data | `records/{slug}/record.md` — tick the checklist, set `validated: true` |
| want a preview before validating | `python _system/tools/render_brief_docx.py {slug}` → `02_output/` (sign-off stays blank) |
| writing a personal story | copy `_templates/personal-note.md` → `records/{slug}/personal-note.md` |
| the field legend or a rule looks wrong | `01_reference/brief-template.md`, `vote-position-rules.md`, `portfolio-relevance.md` — confirm the fix before it's applied to any record |
| a record is validated, ready to send | fill in `01_reference/sender-profile.md` once, then `python _system/tools/finalize_send_pack.py {slug}` → `03_ready-to-send/` (brief + cover email) |
| asked "what's left to do" | scan `_index/log.md` (or `records/*/record.md` frontmatter) |
| no code execution available, want the simplest possible handoff | `_system/portable/start-here/` (5 files, one plain-English instructions file) |
| no code execution available, want more control over which files go in | [`01_reference/chat-only-workflow.md`](01_reference/chat-only-workflow.md) |
| chat-only but the platform can run code, want a real docx not markdown | [`01_reference/chat-only-workflow.md`](01_reference/chat-only-workflow.md) Path B+ |
| the platform won't take a zip or a nested folder | `python _system/tools/build_portable_bundle.py` → `_system/portable/` |
| source workbook/contact-list PDF changed | `python _system/tools/export_plaintext_sources.py` to refresh the CSV exports (then re-run `build_portable_bundle.py` too, if the portable export is in use) |
| something looks off, or you want to know why a rule is the way it is | [`01_reference/decisions-and-lessons.md`](01_reference/decisions-and-lessons.md) |
| you just made a real judgment call, or caught a real mistake | add it to [`01_reference/decisions-and-lessons.md`](01_reference/decisions-and-lessons.md) before moving on — don't let it live only in this conversation |
| this workspace's structure itself needs to evolve (new stage, new form, restructuring) | [`_system/icm-method/SKILL.md`](_system/icm-method/SKILL.md) — the local copy of the method, so you don't need to leave this folder to apply it |

## The one rule

A record isn't done because the data was pulled — it's done when a human has ticked its validation checklist and set `validated: true`. `finalize_send_pack.py` enforces this: it will not produce a send-ready brief or cover email for an unvalidated record. Don't bypass that gate.

## Keep the log current

[`01_reference/decisions-and-lessons.md`](01_reference/decisions-and-lessons.md) is a living log, not a one-time write-up. Any time you make a non-obvious judgment call (a rule, a formula, a format choice) or catch a real mistake (a bug, a wrong assumption, something that silently broke output), add an entry before you consider the task finished. A decision or a bug that only exists in a chat transcript is one the next person — human or agent — will re-litigate or re-break.
